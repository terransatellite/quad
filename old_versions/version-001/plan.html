The quad plan

quad is an AI written in satellite. It writes C++ first and satellite later. It keeps everything it knows as properties, looks through them to write its own programs, and later learns to define new ones itself.

Decided you said it Proposed the design panel's suggestion, waiting on you Done built and running Blocked satellite can't do it yet

01What quad is

The idea Decided

  • quad is written in satellite (.satl) and writes C++ first, then satellite.
  • C++ comes first because it is finished: g++ can check every program quad writes.
  • Knowledge is held as properties with dotted names, e.g. cxx.namespace.std.cout.string.
  • quad flips through its properties and writes its own programs that way.
  • Later it can define new properties. That is the step that makes it "like a living, thinking AI".

Files Decided

  • Every quad file ends in .c4. A text file ends in .text.c4.
  • version.text.c4 holds VERSION=001, REVISION=01, BUILD=0001.

Files quad adds Proposed

  • properties.text.c4: every property
  • goal.text.c4: the lines the program must print
  • program.cxx.c4: the C++ quad writes
  • program.expected.text.c4: what quad predicts it prints
  • program.errors.text.c4, program.output.text.c4: written by the compile line
  • grammar.text.c4: what may follow what (M8)

02What a property holds

Decided
  • Every piece of C++ is its own object.
  • The semicolon ends every command. It is a special class, a special type of object.
  • The objects are held in a satellite.container.multiple<every object type>.
  • Properties have dotted names.
  • The definition is not complete yet.
Proposed
  • A multiple holds one value at a time (tested: a list of two is refused, S301). So each position is your multiple, and a list keeps them in order.
  • Every object class extends one base class, piece.
  • Using a property never changes it. Programs are built in a separate draft.
  • Properties are data in properties.text.c4. Satellite can't load new code while it runs, so data is how quad grows.
satellite.container.list<satellite.container.multiple<word, symbol, header, open_quote, ascii, close_quote, newline, semicolon, hole>> objects

The eight parts of a complete property

Without parts 3 to 6, quad can only glue objects together blindly. Your one cout line alone has about 43 million arrangements, and almost none compile.

NAMEyours

The dotted name. How you and quad refer to it.

OBJECTSyours

The C++ itself, one object per position, in order.

PLACEnew

Where it may go: root, include, function, command, cout_item.

HOLESnew

Gaps inside it, each naming the PLACE it takes and how many fillers.

NEEDSnew

What else the file must hold. std::cout needs #include <iostream>.

DOESnew

What it prints: ascii, number, line_end, holes, nothing.

RECORDnew

TRIED, PASSED, and FAILED= with g++'s first error line.

STATUS · ORIGINnew

seed, untested, proven, broken. Made by you or by quad, and MADE_OF which parents.

03The objects

Every class extends piece, which holds the text, the kind, and the gap written in front. All of them answer call_text(), call_kind() and call_ends_command(). Proposed

word

std::cout int main return 0 #include

symbol

<< ( ) { }

header

<iostream> as one object. Spaced out, g++ fails.

open_quote · close_quote

The same " in two classes, because different things follow each.

ascii

The text between quotes. Empty in a property, filled in the draft. No ", \ or line break.

newline

"\n" as one object of four characters, as you wrote it.

number

Digits. Arrives in M7.

hole

A gap. Names the PLACE it takes, plus least and most fillers.

semicolon

The special class. The only one whose call_ends_command() is true.

Why the semicolon is special

  • quad counts commands by asking every object call_ends_command(). Only the semicolon says yes.
  • A command property must end in exactly one semicolon. quad refuses to load one that doesn't.
  • It is the joint between commands: the one point where the writer steps back out to choose what comes next, and starts a new line.
  • Later it is the knife: quad cuts C++ it reads into commands at each semicolon.
  • It ends commands, not lines. #include lines end at the line end, } ends a block, and the two ; in for ( ; ; ) will need their own class.

05How quad writes C++

Each satl quad.satl run is one turn. The compile happens between turns, because satellite can't start g++ (tested: satellite.system.run gives S110). Proposed

quadRead the goal

goal.text.c4: the lines to print. That is what's "wanted".

quadStart a draft

Copy cxx.program's objects into a new list.

quadFlip through

At each hole, keep properties whose PLACE fits and whose DOES makes what's wanted. Pick one.

quadSplice & nest

Put its objects where the hole was, then fill their holes too. NEEDS fill includes last.

quadShape check & write

No holes left, brackets balance, commands end in ;. Write program.cxx.c4 and the prediction.

you, for nowCompile & run

One g++ line (below). Moves to quad when satellite can run programs.

quad, next turnGate 1 · Shape

Already passed before writing.

quad, next turnGate 2 · Compiler

g++ with -Wall -Wextra must print nothing.

quad, next turnGate 3 · Behaviour

Output equals the prediction and the goal, byte for byte.

quad, next turnRecord

PASS or FAIL goes on every property used. After the first PASS, at most one unproven property per program, so a failure names its cause.

When several properties fit, prefer

  1. proven over untested
  2. the one whose DOES covers more of what's wanted
  3. the narrower one (number before ascii)
  4. the better record
  5. fewer objects

If nothing fits, quad says which hole it couldn't fill. That is its honest "I don't know how yet".

The compile line

rm -f program program.output.text.c4
g++ -std=c++17 -Wall -Wextra -x c++ -o program program.cxx.c4 \
  2> program.errors.text.c4 && timeout 5 ./program > program.output.text.c4

The rm stops an old program from answering when a new one fails to compile.

08The living part

want→flip through properties→write→compile→run→compare→keep or drop→new properties, new goals↺

Every property quad invents starts untested. It must pass the grammar guard, then a test program in which it is the only unproven property.

M7 · proving

Test everything

With no goal, quad flips through every property and tests the next unproven one.

M9 · joining

Remember what worked

Two properties that passed side by side become one. A shortcut, not a new ability.

M10 · wrapping

Name its own functions

Put working code in a function, then move it behind a forward declaration.

later · experiment

Drop and swap

Remove a need or an object, swap std::cout for std::cerr, and learn from what happens.

later · reading

Read real C++

int x = 5; and int y = 7; become int [name] = [number] ;.

later · goals

Set its own goals

"Test every untested property", "use two proven properties never used together".

What this is, and what it isn't

quad's store grows, and everything in it has earned its place by passing g++ and a run. That is real learning in a narrow sense. It is search plus testing: quad only grows through the ways of inventing you give it, it judges programs only by what they print, and it can't run without a person until satellite can start g++. Programs it writes should run only in quad's own folder, with the time limit, never as root.

10Decisions only you can make

Is a list of multiples okay as your "held in a multiple"?
Recommended: yes. Each position is your multiple; the list gives the order. list<piece> also works but loses the closed list of object types.
What is the C++ file called?
Recommended: program.cxx.c4, keeping your .c4 rule. g++ reads it with -x c++. The alternative is program.cpp as a named exception.
Do compiler warnings count as failure?
Recommended: yes. Any message from g++ is a FAIL, so quad never learns habits the compiler complains about.
Who runs g++ between turns?
Recommended: you, by hand, through M5. Save it as a check.sh only when typing gets tiresome. Ask satellite for satellite.system.run.
One quote class or two?
Recommended: two (open_quote, close_quote), because different objects follow each.
Is the semicolon "ends a command", not "ends a line"?
Recommended: yes. #include ends at the line end, } ends a block, and the ; inside for ( ; ; ) gets its own class.
How are properties quad invents named?
Recommended: extend your cxx. tree, e.g. cxx.namespace.std.cout.string.newline, marked ORIGIN=quad.
